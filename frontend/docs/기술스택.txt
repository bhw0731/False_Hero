1. 한 줄 요약
═══════════════════════════════════════════════════════════════════

  Phaser 4 (게임엔진) + Vite 8 (빌드 도구) + Capacitor 8 (모바일 포장)

  게임엔진을 안 썼다고 생각하기 쉽지만, 사실 Phaser 가 그 역할을
  하고 있음. Unity / Unreal 같은 무거운 IDE 형 엔진이 아니라,
  JavaScript 라이브러리 형태라 가벼워서 그렇게 느껴질 뿐.


═══════════════════════════════════════════════════════════════════
2. Vite 8 — 빌드 도구 (게임엔진 X)
═══════════════════════════════════════════════════════════════════

  분류    개발 환경 / 번들러 / 모듈 시스템
  공식    https://vitejs.dev/
  버전    ^8.0.10 (devDependencies)

  역할:
    - npm run dev   → 로컬 개발 서버 (핫 리로드, 파일 저장 시 즉시 반영)
    - npm run build → 배포용 파일 생성 (frontend/dist/)
    - ES Module 시스템 — import/export 문법 그대로 사용 가능
    - Phaser 같은 라이브러리를 npm 으로 설치 → import 로 가져옴

  비유:
    "공구함" — Vite 자체가 게임을 만드는 게 아니라,
              코드 작성 / 실행 / 패키징 환경을 제공.

  옛 방식과 차이:
    옛: <script src="phaser.js"></script> + 모든 코드 한 파일 + global
    신: import Phaser from 'phaser' + 파일별 모듈 분리 + Vite 가 합침

  설정 파일: frontend/vite.config.js (현재 거의 기본값).


═══════════════════════════════════════════════════════════════════
3. Phaser 4.1.0 — ⚠ 이게 게임엔진
═══════════════════════════════════════════════════════════════════

  분류    HTML5 / Canvas 기반 2D 게임엔진 (JavaScript 라이브러리)
  공식    https://phaser.io/
  버전    ^4.1.0 (dependencies)

  Unity / Unreal 과 달리:
    - 별도 IDE / 에디터 X — VSCode 같은 일반 코드 에디터에서 작성
    - 빌드 결과 = HTML + JS + 이미지 → 웹브라우저에서 바로 실행
    - 라이센스 무료 (MIT)

  False Hero 에서 Phaser 가 처리하는 것:

    Scene 시스템:
      Phaser.Scene 상속 → preload / create / update 라이프사이클
      예: SplashScene / MenuScene / StageScene / GameScene
      (frontend/src/scenes/ 폴더)

    Sprite / Graphics:
      Phaser.GameObjects.Sprite     PNG 이미지 그리기
      Phaser.GameObjects.Container  여러 객체 묶음
      Phaser.GameObjects.Graphics   사각형 / 원 / 선 등 도형
      Phaser.GameObjects.Text       글자 렌더링 (TopBar / 모달 라벨)

    물리 / 충돌:
      Phaser.Physics.Arcade — 가벼운 2D 물리 (현재 미사용, 직접 거리 계산)
      Body / Velocity / Collide — 필요 시 활성화 가능

    입력:
      pointerdown / pointerup / pointermove — 터치 + 마우스 통합
      keyboard — 키보드 (현재 거의 미사용)

    사운드:
      scene.sound.add(...) → mp3/ogg 재생, 볼륨 / 페이드 / 크로스페이드
      (frontend/src/systems/SoundManager.js 가 wrap)

    캔버스:
      960×540 고정 (config.width/height) — index.html 에 자동 마운트
      pixelArt: false — 안티앨리어싱 ON (텍스트 / 도형 부드럽게)

    트윈 / 애니메이션:
      scene.tweens.add({ targets, duration, alpha, ... })
      모달 등장 / 토스트 페이드 / 데미지 텍스트 — 전부 Phaser 트윈

  코드에서 어디 보면 됨:
    grep "import Phaser" src/         → Phaser 사용 사이트 모두
    src/main.js                       → Phaser.Game 인스턴스 생성
    src/scenes/*.js                   → Scene 정의
    src/entities/Player.js            → Sprite + 게임 로직

4. Capacitor 8 — 모바일 패키저
═══════════════════════════════════════════════════════════════════

  분류    웹앱 → 네이티브 앱 래퍼 (Cordova 후속작)
  공식    https://capacitorjs.com/
  버전    ^8.3.1 (core / cli / android)

  역할:
    웹 게임 (HTML + JS) → 안드로이드 APK 포장.
    게임 코드는 웹 그대로. Capacitor 가 WebView 컨테이너로 감쌈.

  현재 설정:
    @capacitor/core     코어 API (네이티브 기능 브리지)
    @capacitor/cli      CLI 도구 (sync / build 등)
    @capacitor/android  안드로이드 플랫폼 (자바 / 그래들 프로젝트)

  iOS 추가 시:
    npm install @capacitor/ios
    npx cap add ios
    (맥북 + Xcode 필요)

  빌드 흐름:
    1) npm run build    → frontend/dist/ 에 웹 결과물 생성
    2) npx cap sync     → dist/ 를 안드로이드 프로젝트로 복사
    3) npx cap open android → Android Studio 열림 → APK 빌드

  WebView 한계:
    - 일부 안드로이드 기기에서 Canvas 성능 차이 있음
    - 사운드 자동재생 정책 — 사용자 첫 터치 후 재생 가능
    - 파일 시스템 / 카메라 등 네이티브 API 는 Capacitor 플러그인 필요

5. UI 프레임워크 (Vue / React) — ❌ 안 씀
═══════════════════════════════════════════════════════════════════

  False Hero 의 UI 는 HTML DOM 이 아니라 Canvas 위에 직접 그림.

  TopBar / Modal / 카드픽 / 매점 등 모든 UI:
    Phaser.GameObjects.Container + Text + Graphics 조합으로 구현
    (frontend/src/ui/ 폴더)

  장점 (Canvas UI):
    - 게임 화면과 통합 (배경 / 캐릭터 위에 자연스럽게 오버레이)
    - 트윈 / 효과 일관 (Phaser 트윈으로 페이드 / 스케일 / 회전)
    - DOM 레이아웃 이슈 X (모바일 키보드 / 스크롤 등 신경 X)

  단점:
    - 텍스트 입력 / 복사붙여넣기 어려움 (게임에선 거의 불필요)
    - 접근성 (스크린 리더) 약함
    - 폰트 로딩 — Pretendard 같은 웹폰트 직접 preload 필요

  착각 주의:
    "Vue 썼다" → 아마 Vite 와 헷갈린 것. 둘 다 Evan You 가 만든 거라
    이름이 비슷하지만 완전히 다른 도구.
      Vue  = UI 프레임워크 (반응형 컴포넌트)
      Vite = 빌드 도구 (Vue 외에 React / Phaser 등 다 지원)

6. 프로토타입 / 시작 템플릿 흔적
═══════════════════════════════════════════════════════════════════

  npm create vite 로 프로젝트 생성 시 자동 만들어진 파일 잔재:

    src/main.js              → Phaser 게임 진입점으로 재작성됨 ✓ (사용 중)
    src/style.css            → 빈 / 거의 안 씀 (Canvas 게임이라 CSS 불필요)
    src/counter.js           → 옛 카운터 데모 코드 (사용 X)
    src/assets/javascript.svg → Vite 로고 SVG (사용 X)
    public/vite.svg          → Vite 로고 (사용 X)

  지워도 게임은 정상 작동. 단, 옛 import 가 어딘가 남아있을 수
  있으니 grep 으로 확인 후 삭제 권장:
    grep -r "counter\|javascript.svg\|vite.svg" src/

  이 잔재들은 "프로토타입을 썼다" 의 흔적이라기보다는,
  Vite 가 새 프로젝트 만들 때 기본으로 넣어주는 "데모" 일 뿐임.

7. 정리표
═══════════════════════════════════════════════════════════════════

  도구               역할                  False Hero 에서 쓰임
  ──────────────  ──────────────       ─────────────────────────
  Phaser 4         게임엔진             씀 ★ 핵심
  Vite 8           빌드 / 개발 서버     씀 ★ 핵심
  Capacitor 8      안드로이드 포장      씀 (배포 시)
  Vue              UI 프레임워크        안 씀 ❌
  React            UI 프레임워크        안 씀 ❌
  TypeScript       타입 시스템          안 씀 (순수 JS)
  Tailwind         CSS 프레임워크       안 씀 (Canvas UI)
  Three.js         3D 엔진              안 씀 (2D 만)
  Unity / Unreal   네이티브 게임엔진    안 씀

  False Hero 폴더 구조 핵심 (frontend/):
    package.json     → 의존성 목록 (Phaser / Vite / Capacitor)
    vite.config.js   → Vite 설정
    capacitor.config.json → Capacitor 설정
    index.html       → 게임 진입 HTML
    src/             → 게임 소스 코드
    public/          → 정적 파일 (PNG / 폰트 등)
    docs/            → 명세서 / 가이드 / 본 문서

8. 새로 추가할 수 있는 기술 (선택)
═══════════════════════════════════════════════════════════════════

  필요해질 때 고려:

  TypeScript:
    - 장점: 타입 안전성, IDE 자동완성 강화
    - 단점: .js → .ts 마이그레이션 비용. 카드 / 시너지 객체 타입 정의 필요.
    - 시기: 컨텐츠 안정화 후 (Phase O 이후?)

  단위 테스트 (Vitest):
    - Vite 와 같은 팀이 만든 테스트 러너
    - 카드 apply/revert 정확성 / 시너지 단계 변경 등 회귀 방지
    - 시기: Phase O 시작 전 권장

  PWA (오프라인 / 설치 가능 웹앱):
    - vite-plugin-pwa 추가 → 안드로이드 앱 없이도 "홈화면에 추가" 가능
    - 시기: 웹 배포 시점

  Firebase / 백엔드:
    - 리더보드 / 클라우드 세이브
    - 시기: 멀티플레이 / 랭킹 추가 시점
